PER-STEP AUDIT CONTRACT
-----------------------
For each phase.step, record:
1. Purpose, handler, workflow kind, execution mode, and implementation status.
2. Entry conditions: readiness, date window, predecessors, human authorization.
3. Inputs: exact JSON paths/types, producer and freshness for release/upstream
   data; public parameters, provider responses, time, config and test-only inputs.
4. Work: exact reads, transformations, external writes, and their owning surface.
5. Outputs: separate generated/transient results from external artifacts and
   stored evidence. List exact state paths/key shapes, writer, persist boundary,
   and whether each mutation creates/replaces/merges/appends.
6. Success oracle: independently observable evidence that proves the intended
   operation happened; distinguish override/skip from success.
7. Failure/hold behavior: missing, malformed, stale, partial, unavailable,
   denied, or uncertain evidence; describe what must remain incomplete.
8. Resume/retry: checkpoint before write, interruption boundaries, receipt
   reconciliation, idempotency/deduplication, stale-input rejection. Explain each
   field's consumers, retention/invalidation and recovery/audit relevance.
9. Test recipe: fixed clock, isolated state, deterministic provider fixtures,
   explicit before/after data and unchanged-path assertions, exact provider
   calls and test selectors/results.
10. Coverage gaps, proposed fixes, owner decisions, and next checkpoint.
